# OpenDrop v0.3

로그인 없이 잠깐 파일을 올리고 공유하는 임시 파일 공유 사이트입니다.

**공개 사이트: https://opendrop-zw78.onrender.com**

## 사용

파일 여러 개를 선택하거나 화면에 끌어놓은 뒤 보관 시간을 선택하고 업로드합니다. 비밀번호 버튼을 누르면 별도 팝업에서 보호 설정을 할 수 있습니다. 잠긴 파일을 열 때도 사이트 내부 팝업으로 비밀번호를 입력합니다.

- 파일 1개 최대 500 MiB (524,288,000 bytes), 한 번에 최대 20개 대기열
- 40 MiB씩 나눠 Supabase Private Storage에 저장
- 보관 시간: 10분 / 1시간 / 3시간 / 6시간(기본) / 12시간 / 24시간
- 보관 시간은 업로드를 시작할 때가 아니라 **완료할 때부터** 계산
- 검색, 정렬, 다중 선택 ZIP, 공유 링크, 업로더 삭제
- 이미지/오디오/영상/PDF/텍스트 미리보기. 실제 코덱/PDF 표시는 브라우저 지원에 따름
- 파일 이름과 목록은 공개. 비밀번호는 파일 내용에 대한 접근을 보호

## 복구된 전송 경로

브라우저 런타임은 외부 CDN/SDK를 불러오지 않습니다. 기본 전송은 브라우저에서 서명된 URL로 직접 수행하며, 저장소 직접 연결에 실패하면 인증된 API의 조각 전송 경로로 재시도합니다. 성공한 조각은 다시 보내지 않습니다. 이 재시도는 현재 열린 페이지의 업로드 세션을 사용합니다.

Service Worker가 제공하는 가상 URL로 원본 파일과 ZIP을 스트리밍합니다. 다운로드는 iframe 탐색 요청을 사용합니다. Chromium 모바일 모드에서 `a[download]`로 Service Worker 응답을 받으면 다운로드가 취소되는 문제를 재현했고, iframe 방식으로 저장 완료를 확인했습니다. ZIP은 불필요한 서버 복사본 없이 생성되는 무압축 ZIP입니다.

Service Worker를 사용할 수 없는 환경에는 Blob 방식이 있습니다. 이 경로는 대용량 파일에서 메모리를 많이 사용하므로 안내 창을 표시합니다. 업로드 중에는 탭을 열어 두세요.

## 화면

제공된 DESIGN.md의 크림색(#fdfcfc), 검은 잉크색(#201d1d), 고정폭 글꼴 스택, 4px 버튼, 얇은 경계선, ASCII 표기, 단일 어두운 터미널 영역을 적용했습니다. 그림자/그라디언트는 사용하지 않습니다. Berkeley Mono 파일은 포함되어 있지 않으며 설치된 글꼴 또는 시스템 고정폭 대체 글꼴을 사용합니다.

## 구조

- `index.html`: 접근 가능한 페이지/비밀번호/미리보기/확인 팝업
- `style.css`: 반응형 스타일
- `app.js`: 다중 업로드, 상태, API 연결, 오류 복사, 공유/삭제
- `transfer.js`: 스트림 재결합, 범위 요청, CRC32, ZIP 생성
- `sw.js`: 모바일 다운로드/미리보기 가상 URL. 앱 화면을 캐시하지 않음
- `qa/`: 명시적으로 실행하는 브라우저 검증 도구와 검증 기록

웹은 Render Static Site, API/DB/Storage/매분 정리 작업은 기존 Supabase 프로젝트에서 실행됩니다. 이 저장소의 정적 파일에 서비스 키나 관리자 키는 포함하지 않습니다. API URL은 이 배포의 Supabase 프로젝트를 가리킵니다.

## 무료 한도

애플리케이션의 전체 파일 예약 용량은 900 MiB입니다. 파일당 500 MiB 지원이 전체 저장 용량 증가를 뜻하지는 않습니다. 공간이 부족하면 새 업로드를 차단합니다. 저장 공간뿐 아니라 호스팅 사업자의 전송량/요청량 무료 한도도 적용됩니다. 유료 서비스/유료 디스크를 추가하지 않았습니다.

만료 시 새 접근을 차단하고, 매분 정리 작업이 Storage 객체를 삭제한 뒤 DB 기록을 제거합니다. 정리 실패 시 재시도하므로 실제 삭제가 항상 정확히 1분 안에 끝난다는 보장은 없습니다. 이미 내려받은 파일을 회수할 수는 없습니다.

## 실행 및 검증

로컬에서는 프로젝트 루트에서 `python -m http.server 4173`을 실행한 뒤 `http://localhost:4173`을 엽니다. `file://`로 열면 Service Worker가 동작하지 않습니다.

브라우저 회귀 테스트는 `npm run test:browser`로 명시적으로 실행합니다. Chromium 모바일 화면 설정과 실제 Supabase 백엔드를 사용하며, 테스트 파일을 업로드하고 다운로드한 실제 바이트를 비교한 뒤 자신이 만든 파일을 정리합니다. 이 테스트는 실제 저장소/전송량을 사용합니다. 일반 배포마다 자동으로 대용량 파일을 올리는 작업은 하지 않습니다.
